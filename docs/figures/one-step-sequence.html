One step of one match, and where it goes

A player moves. The server records a span that says which match and which player, exports it over OTLP to a collector that batches it into Jaeger, and exposes the numbers Prometheus pulls — so the same request answers "what happened" and "how often".

measured: 30 traces, 29 carrying the match id · p99 of a step 0.99 µs at 4.18 steps/s · both scrape targets up · 4 alert rules loaded
The span is the question, the metric is the count

"Which match was slow" is answered by the trace, because the match and the player are on it. "Is this happening more than yesterday" is answered by the counter. A dashboard built on one of them alone sends the reader to the wrong tool.

Why the collector is a separate container

The application speaks OTLP and names no backend, so moving traces from Jaeger to Tempo is a line in a config file rather than a redeploy — and the batching, the memory limit and the retries live where they can be tuned without touching the game.
